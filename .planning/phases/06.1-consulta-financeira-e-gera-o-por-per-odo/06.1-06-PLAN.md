<objective>
Implementar a geração retroativa/backfill de parcelas (PARCELA-06): contratos com `periodo_inicio` E `periodo_fim` passam a ter todos os meses do período gerados de uma vez — incluindo meses já passados — em vez de só mês atual + próximo. Contratos com só uma das datas, ou nenhuma, continuam exatamente como estavam.

Esta é a mudança de maior risco da fase: a primeira vez que este código roda contra produção pode criar dezenas de parcelas "Vencida" de uma vez para contratos antigos com as duas datas já cadastradas. Por isso a Task 1 é um `checkpoint:decision` que roda as consultas de pré-voo já escritas em `.planning/sketches/preflight-task.md` e exige revisão humana dos números antes da Task 2 (a implementação) prosseguir — D-17, mesmo espírito do `checkpoint:decision` que gateou `supabase db push` na Phase 4, adaptado para uma mudança de camada de aplicação em vez de DDL.

Purpose: PARCELA-06 reabre uma decisão que a spec original tinha fechado como "sem backfill" — o usuário reverteu essa decisão explicitamente (D-13), mas o volume real precisa ser visto por um humano antes do código rodar pela primeira vez, não depois.
Output: geração retroativa funcionando, com o volume real conhecido e revisado antes do primeiro deploy.
</objective>

Este plano não cria símbolo de banco novo — ver `## Artifacts this phase produces` em `06.1-01-PLAN.md` para as funções puras alteradas (`competenciasDoPeriodo`, `temPeriodoCompleto`, `competenciasAlvoParaCard`, `parcelasFaltantes`, `garantirParcelas`).
