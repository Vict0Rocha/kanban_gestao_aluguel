## Trust Boundaries

| Boundary | Description |
|----------|--------------|
| navegador -> `searchParams` -> Server Component | Os quatro campos de filtro são entrada controlada pelo usuário (via URL); cruzam a fronteira cliente->servidor a cada `router.push` |
| `searchParams` -> Supabase query builder | Nenhum valor de filtro é interpolado em SQL cru — tudo passa pelos métodos `.eq()`/`.ilike()`/`.gte()`/`.lt()` do query builder, parametrizados pelo supabase-js |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-06.1-16 | Tampering | Injeção via parâmetro de filtro | high | mitigate | Todo valor de `searchParams` passa por `.eq()`/`.ilike()`/`.gte()`/`.lt()` do supabase-js, nunca por interpolação de string em SQL; portão automatizado confirma a presença desses métodos, não de template string SQL |
| T-06.1-17 | Denial of Service | `id` não numérico ou período malformado derrubando a página | medium | mitigate | `id` só vira filtro se `Number.isInteger(Number(id))`; `periodo` fora do formato `type="month"` é ignorado silenciosamente em vez de lançar |

| T-06.1-19 | Elevation of Privilege | Consulta filtrada usando `service_role` por engano | critical | mitigate | `page.tsx` continua recebendo o cliente Supabase de `createClient()` (sessão do usuário), sem nenhum cliente novo introduzido neste plano |
