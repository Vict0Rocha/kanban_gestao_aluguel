Seção 1 — a coluna nova em `cards`: `alter table public.cards add column if not exists ativo boolean not null default true;` (D-01). Comentar que o Postgres 11+ preenche as linhas existentes com o default sem reescrever a tabela e sem disparar o trigger `cards_set_updated_at`, por isso não é preciso um `update` de backfill separado.

Seção 2 — `create table if not exists public.parcelas` com exatamente as colunas: `id uuid primary key default gen_random_uuid()`, `card_id uuid not null references public.cards(id) on delete cascade`, `competencia date not null`, `vencimento date not null`, `valor_original numeric(12,2) not null`, `status text not null default 'aberta'`, `conciliada_em timestamptz`, `conciliada_by uuid references public.profiles(id)`, `created_at timestamptz not null default now()` (D-02).

Escolha de discrição registrada em comentário: `status` é `text` com CHECK, não enum do Postgres — porque adicionar valor a enum exige DDL e o CHECK nomeado é derrubável/recriável no mesmo estilo já usado em `cards`. Seção 3 — constraints de `parcelas`, cada uma precedida de `alter table public.parcelas drop constraint if exists <nome>;` para deixar o arquivo reexecutável (mesmo padrão do bloco de validação da migration de hardening):
