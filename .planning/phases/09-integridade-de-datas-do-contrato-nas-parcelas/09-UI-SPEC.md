# Phase 9 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

---

## Scope Note

This phase's only new UI surface is a **confirmation step in an existing save flow** (D-05 in `09-CONTEXT.md`): when a user edits `periodo_inicio`/`periodo_fim` on `card-detail-dialog.tsx` and the edit would delete one or more orphaned parcelas (no payment/lançamento, now outside the new period — D-01/D-02/D-03), the save flow must show the count and require an explicit confirming click before the deletion + save happens.

**No new design tokens, no new components, no new registry.** This phase reuses the project's already-established shadcn primitives (`AlertDialog`, `Button`) and copy tone verbatim from the two existing precedent dialogs in the same file family: `web/src/components/kanban/excluir-contrato-dialog.tsx` (irreversible-delete tone, pre-flight check pattern) and `web/src/components/kanban/arquivar-contrato-dialog.tsx` (pre-flight count-and-warn pattern). This UI-SPEC exists to lock the *copy* and *state machine* of the new confirmation step, not to introduce new visual language.

The D-08 cleanup of the 27 existing orphaned parcelas is a one-time SQL Editor script (same pattern as every other production migration in this project) — not a UI surface. Out of scope for this document.

## Copywriting Contract

Exact strings for the new confirmation step. Component name suggestion for the plan: `ConfirmarPodaParcelasDialog` (or inline state in `card-detail-dialog.tsx` — planner's call), nested/opened from within the existing `CardDetailDialog` save flow, not a new standalone entry point.

| Element | Copy |
|---------|------|
| Trigger condition | Fires only when `periodo_inicio` and/or `periodo_fim` actually changed on submit **and** the pre-flight count of deletable orphans (D-02 criteria) is > 0. If the count is 0 (the common case), save proceeds exactly as today — **zero new friction**, no dialog. |
| Pre-flight loading label | Submit button reads `"Verificando..."` while the orphan count is being fetched (before deciding whether to show the confirmation dialog) — same pattern as `"Conferindo parcelas em aberto..."` / `"Conferindo o histórico financeiro..."` in the two precedent dialogs |
| Dialog title | `"Esta alteração vai apagar parcelas"` |
| Dialog description — singular (count = 1) | `"{endereço} — o contrato {numero}: 1 parcela ficou fora do novo período e será apagada. Só parcelas sem nenhum pagamento ou lançamento são apagadas — as demais continuam intactas. Esta ação não pode ser desfeita."` |
| Dialog description — plural (count > 1) | `"{endereço} — o contrato {numero}: {N} parcelas ficaram fora do novo período e serão apagadas. Só parcelas sem nenhum pagamento ou lançamento são apagadas — as demais continuam intactas. Esta ação não pode ser desfeita."` |
| Primary CTA (confirm) | `"Confirmar e salvar"` — exact string from D-05, `AlertDialogAction variant="destructive"` |
| Confirm CTA — saving state | `"Salvando..."` (button disabled while in flight, matches every other dialog's saving-state convention in this codebase) |
| Cancel | `"Cancelar"` (`AlertDialogCancel`, default) — returns to the open `CardDetailDialog` form with the edited (unsaved) date values intact, so the user can adjust dates instead of losing their edit |
| Pre-flight check failed (network/error) | Inline in the existing `CardDetailDialog` error slot (same `text-sm text-destructive` used today): `"Não foi possível confirmar as mudanças no período. Tente novamente."` — **fail-closed**: unlike the pre-flight checks in the two precedent dialogs (which fail-open because the server is a backstop that can only *block*), this pre-flight failing must **not** silently proceed to a deletion the user never saw a count for. Submit stays enabled for retry. |
| Save fails after confirmation (server rejects) | Inline inside the confirmation dialog, same slot pattern as `excluir-contrato-dialog.tsx`: `"Não foi possível salvar as alterações. Tente novamente."` (via `erroDoBanco()` sanitization if the rejection is a raw DB error) |
| Unchanged: primary CTA when 0 orphans (no confirmation shown) | `"Salvar"` / saving state `"Salvando..."` — **exactly as today**, no copy change |
| Unchanged: existing generic save error | `"Não foi possível salvar. Tente novamente."` (already in `card-detail-dialog.tsx:94`) — untouched |
| Empty state | Not applicable — this phase adds no list/collection view, only a confirmation step inside an existing form dialog |
| Destructive confirmation | `Confirmar e salvar`: see dialog title/description rows above. Deliberately **lighter-weight** than `ExcluirContratoDialog`'s typed-text confirmation (`"excluir {numero}"`) — D-05 explicitly reserves that friction level for deleting the whole contract, not for pruning orphaned parcelas as a side effect of a date edit. |

## UI Considerations

Applicable state considerations resolved: 6 covered, 1 backstop, 0 unresolved.

| Category | Element(s) | Status | Resolution / Reason |
|----------|------------|--------|---------------------|
| zero-one-many | orphan count in confirmation dialog | ✅ covered | Count = 0 → no dialog, save proceeds unchanged (see Copywriting row "Trigger condition"). Count = 1 → singular copy row. Count > 1 → plural copy row with `{N}`. |
| loading | pre-flight orphan check | ✅ covered | Submit button shows `"Verificando..."` while the count is fetched, disabled during the check — see Copywriting row "Pre-flight loading label" |
| loading | confirmation dialog save | ✅ covered | Confirm button shows `"Salvando..."` disabled while in flight — see Copywriting row "Confirm CTA — saving state" |
| error | pre-flight check fails | ✅ covered | Fail-closed inline error in `CardDetailDialog`, submit re-enabled for retry — see Copywriting row "Pre-flight check failed" |
| error | confirmed save rejected by server | ✅ covered | Inline error inside the confirmation dialog, sanitized via `erroDoBanco()` — see Copywriting row "Save fails after confirmation" |
| populated | confirmation dialog with count > 0 | ✅ covered | Title + description rows above; destructive-variant confirm button |
| overflow | very large orphan count (e.g. a contract edited from a 5-year span down to 1 month) | 🧪 backstop | Count renders as a plain number in the existing sentence template — no truncation/wrapping concern expected at any realistic magnitude (production scale is ~46 contracts total), but not explicitly visually verified against a triple-digit count. Planner/executor should sanity-check the sentence still reads cleanly if `{N}` is 3+ digits. |
