# Phase 8 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

**Scope note:** This phase is a strict ADD to the existing `/relatorios` route (`web/src/components/reports/reports-view.tsx`). Every pixel of the current page (h1, subtitle, existing filter card with `SearchField`/`STATUS_OPTIONS` chips/column chips, `StatTile` row, `ColumnBarChart`, `ContractsTable`) is byte-for-byte unchanged. ## Layout & Component Contract (phase-specific, informed by Claude's Discretion in 08-CONTEXT.md)

**Visual hierarchy (primary anchor for the composited page).** Before generation, the new filter panel plus its "Gerar relatório" CTA is the primary visual anchor of `/relatorios` — it sits first, right below the page subtitle, and is the only actionable surface this phase adds above the fold. After a report is generated, the anchor shifts to the four-category result grid (count + total per category), which is the actual payoff the user came for; the filter panel becomes secondary, available to refine and re-run. This is a two-stage hierarchy by design (CONTEXT.md's "não é um afterthought, é o ponto de entrada principal"), not an oversight — nothing about the existing page's own hierarchy (h1, contract-status chips, StatTiles, ColumnBarChart, ContractsTable) changes.

**1. Filter panel — position and mechanics**
Insert directly after the existing subtitle block (`reports-view.tsx` line 138, "Uma visão geral da carteira...") and before the existing filter card (line 142 `<div className="flex flex-col gap-3 rounded-2xl border...">`). A new, separate component (e.g. `FiltroRelatorioFinanceiro`, sibling file to `filtro-parcelas.tsx` but under `components/reports/`) — never import or move `FiltroParcelas` itself. Mirror its mechanics exactly:
- `Collapsible`/`CollapsibleTrigger`/`CollapsiblePanel` from `@/components/ui/collapsible`.
- Closed by default; opens automatically if the panel's own query params are present on load (same rule as `FiltroParcelas`' `filtrosAtivos` prop) — since D-04 makes this a client-local "Gerar relatório" flow rather than URL-driven per-keystroke, "params present" here means: local form state is non-empty AND a report has already been generated in this session (e.g. via a `?relFiltro=1`-style marker, or simply keep it session/component state — no URL round-trip is required by D-04, this is planner's call, not a design constraint).
- Panel surface: `mt-3 rounded-2xl border border-border bg-card px-5 py-4` (verbatim class string from `FiltroParcelas`).
- Trigger button: `Button variant="outline" size="sm"` with `Filter`/`X` icon swap (verbatim from `FiltroParcelas`).

**2. Filter fields inside the panel**
Three text/date fields + one chip row, in this order: Imóvel (text, `ilike` semantics — same free-text pattern as Proprietário/Inquilino in `FiltroParcelas`) → Proprietário (text, same pattern) → Período (`type="month"`, same as `filtro-periodo`) → Situação (chip row, see below). Use the same `flex flex-col gap-1.5` field wrapper + `Label` + `Input` pattern as `FiltroParcelas`. Layout: a responsive grid (`grid-cols-[repeat(3,1fr)] gap-3` for the three text/date fields, chip row full-width beneath, action buttons row beneath that) — do not force the 4-column-plus-auto grid of `FiltroParcelas` verbatim since this panel has one more filter dimension (situação chips need full width to wrap comfortably); a stacked layout (fields row, then chip row, then action row) is the correct adaptation, not a violation of the reused pattern.

**3. Situação chips**
Reuse `FilterChip` and the `toggle()` helper from `reports-view.tsx` verbatim (import or lift into a shared location — planner's call) for a new `SITUACAO_OPTIONS` array: `paga` → "Pagas", `a_vencer` → "A vencer", `vencida` → "Vencidas", `conciliada` → "Conciliadas". Same multi-select-toggle semantics as `STATUS_OPTIONS` (empty set = "Todas", no filter applied).

**4. "Gerar relatório" button**
`Button variant="default"` (primary), placed at the end of the panel's action row alongside a `Button variant="ghost"` "Limpar filtros" (mirrors `FiltroParcelas`' Consultar/Limpar pair). Per D-04, this button is the only trigger for the query — no field change runs anything live.

**5. Four-category result display**
Use `StatTile` (`web/src/components/reports/stat-tile.tsx`) as-is, unmodified, one per category, in a `grid gap-4 sm:grid-cols-2 xl:grid-cols-4` row (same grid class already used for the page's existing 4 `StatTile`s at line 212) — placed below the new filter panel, above or below the existing `StatTile` row per planner's layout call, but visually as its own labeled group (wrap in a `<div>` with a small heading "Relatório financeiro" so it reads as a distinct block, not a merge into the existing 4-tile row). Each tile: `icon` (suggest `CheckCircle2` pagas, `Clock` a vencer, `AlertCircle` vencidas, `Lock` conciliadas — same icon-to-situação mapping already established in `ParcelaSituacaoBadge`, for visual consistency across the app), `label` (category name), `value` (parcela count as a plain number string, e.g. `"12"`), `hint` (the money total via `formatCurrency`, e.g. `hint="R$ 4.200,00"`). Do **not** invent a new visual pattern (table, custom card) unless `StatTile`'s two-line layout (icon+label, then big number, then optional hint) cannot fit both count and money total legibly — if so, the fallback is a small variant of `StatTile` (new `secondaryValue` prop) rather than a wholly new component, to keep this page visually uniform.
Tone: `vencidas` may use `tone="alert"` (matching `StatTile`'s existing alert-tone convention, reserved for counts needing action) only if `count > 0` — same rule already applied to "Contratos a vencer" at line 229 of `reports-view.tsx`.

**6. Data/behavior notes for the planner (not visual, but shape the copy/UI states above)**
- Archived/inactive contracts count toward all four totals (D-05) — no filter/query on this new panel should silently apply the `arquivado_em is null` filter that `relatorios/page.tsx` uses for the existing contract-status report; that filter must not propagate to the new financial-report query.
- Período filter applies to `competencia`, not `vencimento` (D-08) — matches the Financeiro tab's existing period filter semantics, so users moving between the two screens don't hit a surprising mismatch.
- Vencida/a-vencer split is computed on read against `hojeEmCuiaba()` (already piped into `ReportsView` as `todayISO`), never stored (FINREL "Pilares cruzados").
