<objective>
Construir o botão "Reordenar" do Board ponta a ponta — do clique no botão até a gravação em lote no banco —
como uma única fatia vertical: exportar `GAP` de `position.ts`, escrever `reordenarCardsAction` (Server
Action nova, modelada em `moveCardAction`) + o wrapper `reordenarCards` (queries.ts), o componente novo
`ReordenarDialog` (`reordenar-dialog.tsx`, sem precedente exato neste projeto — composto de dois padrões já
existentes) e o wiring em `board.tsx` (botão ao lado do `SearchField`, `handleReordenar` usando
`persistOrRevert`). Fecha REORD-01/02/03 (D-06 a D-11, `16-CONTEXT.md`).

Capacidade independente da migração de arquivamento (planos 16-01/16-03/16-04): não toca schema, não
precisa de nenhuma aplicação em produção além do deploy normal do app — RLS de `cards` (`is_team_member()`)
já é a fronteira de autorização real, igual a toda outra Server Action deste projeto.

Purpose: um usuário com muitos cards espalhados pelo board hoje precisa arrastar um por um para reorganizar
em massa; este plano dá um caminho de um clique, sem tocar no arraste individual já existente.
Output: botão "Reordenar" funcional em produção, movendo cards em lote com a ordem visual preservada.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|--------------|
| navegador → `reordenarCardsAction` | Server Action alcançável fora da interface (é um endpoint POST de verdade); a única fronteira de autorização real é a policy `"team full access cards"` (`is_team_member()`), a mesma de toda outra escrita em `cards` |
| cliente → array `cardIds` | O cliente monta o array de ids a partir do estado já carregado do Board (nunca de input livre digitado), mas a Server Action não confia nisso — revalida cada `id()` e o tamanho do array por conta própria |
